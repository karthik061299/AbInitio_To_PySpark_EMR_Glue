### 1. INPUT FILE (Raw Transactions from AWS S3)

  - **✅ Correct** — Schema, delimiter, file path, and parameter mapping match perfectly.

### 2. INPUT FILE (Product Dimension)
- **Ab Initio:** Component ID 200, reads product dimension file from $(PROJECT_DIR)/data/dim/product_dim.dat, applies $(PRODUCT_DIM_DML) schema.
- **PySpark:**
  - `spark.read.option("delimiter", "|").option("header", "false").schema(product_dimension_schema).csv(product_dim_path)`
  - Path: `f"{PROJECT_DIR}/data/dim/product_dim.dat"`
  - **✅ Correct** — Schema, delimiter, file path, and parameter mapping match perfectly.

### 3. REFORMAT (Cleanse & Validate)
- **Ab Initio:** Component ID 300, calls $(CLEANSE_XFR_FILE) = cleanse_validate.xfr, outputs $(CLEAN_DATA_DML_FILE), splits rejects with error_message.
- **PySpark:**
  - `transform_cleanse_transform(raw_transactions_df)` matches XFR logic:
    - Casts txn_id to DecimalType(10,0)
    - Converts txn_date_str to date format
    - Calculates total_amount from quantity_str * unit_price_str
    - Initializes tax_amount, final_bill, loyalty_points to 0
  - Reject logic: `isnull`, `length(trim())`, `total_amount <= 0` conditions match Ab Initio validation requirements.
  - **✅ Correct** — XFR function placement, transformation logic, and reject handling are accurate.

### 4. DEDUP SORT (Remove Duplicate Transactions)
- **Ab Initio:** Component ID 400, deduplicates by {txn_id} key, outputs unique records and duplicates.
- **PySpark:**
  - `dropDuplicates(["txn_id"])` matches deduplication key specification.
  - **✅ Correct** — Deduplication logic and key match exactly.

### 5. JOIN (Enrich with Product Info)
- **Ab Initio:** Component ID 500, inner join on {in0.product_sku, in1.product_sku}, enriches with category and standard_cost, outputs unused records.
- **PySpark:**
  - `deduped_df.alias("txn").join(product_dim_df.alias("prod"), col("txn.product_sku") == col("prod.product_sku"), "inner")`
  - `.select()` includes all required columns: txn_id, store_id, txn_date, product_sku, category, total_amount, standard_cost, tax_amount, final_bill, loyalty_points.
  - Product lookup misses handled via `left_anti` join matching Ab Initio unused0 port.
  - **✅ Correct** — Join keys, type, enrichment columns, and miss logic are perfectly implemented.

### 6. REFORMAT (Apply Pricing Rules)
- **Ab Initio:** Component ID 600, calls $(PRICING_XFR_FILE) = pricing_rules.xfr, outputs $(CLEAN_DATA_DML_FILE).
- **PySpark:**
  - `transform_pricing_logic(enriched_df)` matches XFR logic:
    - tax_rate = 0.085
    - tax_amount = total_amount * tax_rate
    - final_bill = total_amount + tax_amount
    - loyalty_points = floor(total_amount / 10)
  - **✅ Correct** — XFR function placement and pricing calculations are accurate.

### 7. SORT (Prepare for Rollup)
- **Ab Initio:** Component ID 700, sorts by {store_id, txn_date} key for rollup preparation.
- **PySpark:**
  - `orderBy("store_id", "txn_date")` matches sort keys exactly.
  - **✅ Correct** — Sorting logic and keys are perfectly aligned.

### 8. ROLLUP (Store Aggregation)
- **Ab Initio:** Component ID 800, calls $(ROLLUP_XFR_FILE) = store_rollup.xfr, aggregates by {store_id, txn_date}, outputs $(SUMMARY_DML_FILE).
- **PySpark:**
  - `transform_rollup_logic(sorted_df)` matches XFR logic:
    - groupBy("store_id", "txn_date")
    - sum("final_bill").alias("total_gross_sales")
    - sum("tax_amount").alias("total_tax_collected")
    - count("*").alias("total_transaction_count")
    - withColumn("report_date", col("txn_date"))
  - **✅ Correct** — Aggregation logic, grouping keys, and schema match perfectly.

### 9. OUTPUT FILE (Final Summary)
- **Ab Initio:** Component ID 900, writes to $(PROJECT_DIR)/data/out/daily_summary.dat, applies $(SUMMARY_DML_FILE).
- **PySpark:**
  - `summary_df.coalesce(1).write.mode("overwrite").option("delimiter", "|").option("header", "false").csv(summary_output_path)`
  - Path: `f"{PROJECT_DIR}/data/out/daily_summary.dat"`
  - **✅ Correct** — Output logic, file path, and format match exactly.

### 10. OUTPUT FILE (Cleanse Rejects)

### 11. OUTPUT FILE (Product Lookup Misses)

## Flow Connections Validation

**Ab Initio Flow Sequence (from .mp file):**
1. Read_AWS_S3 (100) → Cleanse_Data (300)
2. Read_Product_Dim (200) → Enrichment_Join (500, in1)
3. Cleanse_Data (300, out) → Dedup_Transactions (400)
4. Cleanse_Data (300, reject) → Write_Cleanse_Rejects (1000)
5. Dedup_Transactions (400) → Enrichment_Join (500, in0)
6. Enrichment_Join (500, out) → Apply_Pricing (600)
7. Enrichment_Join (500, unused0) → Write_Product_Misses (1100)
8. Apply_Pricing (600) → Sort_for_Rollup (700)
9. Sort_for_Rollup (700) → Store_Aggregation (800)
10. Store_Aggregation (800) → Write_Summary (900)

**PySpark Flow Sequence:**
1. raw_transactions_df → cleansed_df (transform_cleanse_transform)
2. product_dim_df → enriched_df (join)
3. cleansed_df → clean_data_df (filter)
4. cleansed_df → reject_data_df (filter)
5. clean_data_df → deduped_df (dropDuplicates)
6. deduped_df + product_dim_df → enriched_df (inner join)
7. deduped_df + product_dim_df → product_misses_df (left_anti join)
8. enriched_df → priced_df (transform_pricing_logic)
9. priced_df → sorted_df (orderBy)
10. sorted_df → summary_df (transform_rollup_logic)
11. Output: summary_df, reject_data_df, product_misses_df

**✅ Flow Order Match:** The PySpark code follows the exact component sequence and data flow as defined in the Ab Initio graph.
